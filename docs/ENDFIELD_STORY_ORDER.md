# 终末地：把解包出的剧情按任务步骤排列

> 2026-10-22（v0.16.0 起所有有步骤的任务都这样排）。代码：`lib/core/gamedata/build/endfield/endfield_level_data.dart`（解码关卡数据）、
> `endfield_story_order.dart`（排列）、`endfield_stories.dart`（写进库、写报告）。建库参数见 `GAMEDATA_BUILD_PIPELINE.md` §9.2。
> 改这里的规则前先读完本文，尤其是 §6 怎么验证。

## 1. 要解决的问题

终末地一个任务的文字分散在几张表里：对话（`dlg_`）、过场动画（`cutscene_` / `cs_video_`）、通讯（`radio_`）、远程通话、闲话（`envTalk_`）、短信（`sns_`），
每种各自编号，编号之间没有先后关系。0.12 起“一个任务一篇”，按种类分块、块内按编号，读起来是“先看完所有对话，再看所有通讯”，与游戏里的顺序不符。
游戏里的先后由**任务步骤**决定：每一步有目标、完成条件、追踪的位置，对话由关卡脚本、NPC、触发区域在某一步里播放。
这些都在客户端的关卡数据里，所以顺序可以从数据里推出来，不靠猜，也不靠 Wiki。

fz.wiki 的任务页也是按步骤挂对话（它也解码关卡脚本，位置全标“估计”）；我们自己解码，规则与依据都写在报告里。

## 2. 数据从哪里来

都在热更新层导出的 JsonData（`<unpack>/persistent/Data/Json`，它带全套关卡数据；`unpack_endfield.ps1` 已经导出）：

| 数据 | 位置 | 用来 |
| --- | --- | --- |
| 任务定义 | `MissionRuntimeAsset/<任务>.json`（明文 JSON） | 步骤（`questDic`）、前置步骤（`prevQuestIdList`）、目标文字、完成条件、追踪信息（位置、NPC、短信） |
| 关卡脚本 | `LevelScriptData/<关卡>/<脚本>.json`（名字叫 json，其实是二进制） | 动作链：播放哪段对话、等哪段结束、触发区域、开关分段、移动 NPC、按步骤状态分支 |
| 关卡的任务子数据 | `LevelData/<关卡>/…_lv_data_sub_<任务>` | 以任务/步骤状态为条件的实体组（某组 NPC 只在某几步出现）、区域通讯 |
| NPC 与路人 | `WorldEntityRegistry`、`NpcProxyExDataTable` 等 | 谁说哪段话、站在哪里、每个状态说哪段 |
| 任务区域 | 区域表（按 `subDataParentId` 所在文件夹分关卡） | 步骤目标与区域通讯的坐标 |
| 字符串 | `StringPool/StringPool<n>.byte` | 二进制数据里的字符串都是池里的编号 |

### 2.1 二进制格式（2026-10-18 客户端）

- **StringPool**：按 n 拼接；文件头 `USPC` 前可能多 4 字节，之后是 LZ4 块：`<条数> <条数+1 个偏移> <字符串>`，每条末尾 4 字节不属于它；
  偏移倒着的条目当空串，但占着编号。
- **记录**：`<标签> <成员数> 00 <_ID> 00 <uid>`，接 `01 00 00 00 01 01 <next>`（分叉 `00 01 ff*4 <n> <ids>`）；`fa <u16>` 是两字节标签。
  头部记录 `01 00 00 00 00 01 00*8 (00|01) <入口>`。
- **类型名靠 uid 对照**：kit 的联合标签表（`levelscript_union_tags.json`）与最后一个明文客户端同一构建，按两个客户端里同一 uid 的记录对出新客户端的标签，
  `levelScriptTypeNames` 只留用到的。**换客户端要重对一遍**：类型名错了，下面的规则全部失效而不报错。
- **触发区域**：`<槽位> 01 08 00 ff*4 00 01 00 00 00 <?> 00*4 <xyz> <浮点> <旋转> <形状 1 盒/2 球> <盒尺寸>`。槽位后的浮点有时是旋转角，不能当半径。
- **分支**：`IfElseAction` 是 `04 01 <条件> ff*4 fe ff ff ff <then> <else>`。
- **子数据**：实体组 `0d 03 <比较> <状态> <任务>`（任务）、`12 03 …`（步骤），状态 0–5 = 无/可接/进行中/完成/失败/禁用，后接 `<n> <n 个逻辑编号>`；
  区域通讯 `<半径> <通讯> 00*8`，前面的 `04 <状态> <步骤>` 列表里状态 2 的那一步就是它起作用的步骤。

### 2.2 容易认错的

- `ShowSceneDecorationNew` 开关的是**分段**，不是“启用脚本”。分段编号可能是 NPC 代理的逻辑编号（`npcProxyBriefInfos`），也可能是同号脚本；是 NPC 的就只开关 NPC。
- 脚本激活时按“某步是否完成”恢复分段状态（`IfElseAction` + `CheckMissionOrQuestIsComplete/IsProcessing`），这给出分段在哪几步打开；对话期间临时隐藏的不算。
- 任务区域 id 在不同关卡里重名，要按区域所在关卡分，否则路线会混进别的关卡的坐标。
- 试过“进入触发球就算触发”：很多脚本之后才被激活，整体变差，撤回。

## 3. 排列的规则

### 3.1 步骤的顺序

按前置步骤（`prevQuestIdList`）拓扑排序，同层按编号；不是只按编号（编号不总是先后）。

### 3.2 每段对话归哪一步（强到弱）

1. **步骤点名**：完成条件、`clientActionMap` 写着这段对话，或这一步追踪的短信、追踪的 NPC 说它。
2. **步骤点名的脚本**：步骤的条件点名一个脚本，脚本播放它、等它结束，或驱动说它的 NPC；区域通讯的状态列表要这一步进行中。
3. **同一条动作链**上已定位的对话、子数据里以这一步为条件的物件组。
4. **按位置**：它自己的位置（触发区域、所在物件、说它的 NPC 或路人）离哪一步的**路线**最近。
   路线是“上一个目标 → 这一步的目标”连成的折线（多个目标按 追踪 → 条件区域 → 点名对话的位置 连），没有目标的步骤借下一步的目标但不移动起点。
   候选只在它的分段打开、它等的 NPC 在场的那几步里选。几步差不多近时依次看：编号与已定位的同种对话一致；它的脚本等的步骤；
   两步一样近时取离同一脚本里已定位对话较近的那一步；物件就在前一步自己的目标 5 米内时归前一步（只对物件，路人不算）。
   离所有路线都远（大于 50 米）的不作依据。
5. **没有任何依据**：按编号放在同种对话旁边；没有依据的过场放在本篇末尾。

### 3.3 一步之内

按路线上的进度，再按种类：短信 → 闲话 → 通讯 → 远程通话 → 过场 → 对话（开发者 2026-10-21）；完全相同的触发区域是同一时刻，对话先、通讯后。

- **进门演出**：带镜头、禁止移动或放慢脚步（`SetCharacterGait`）的链按进入时算；同一脚本里放慢脚步、到某段对话才恢复的，脚本里物件的台词排在那段对话之后。
- **追踪的 NPC 有几行**（`NpcProxyExDataTable` 每行是一个状态）：最后一行才是这一步要的，前面的是上一步进行时找它说的话，放在它站的地方附近已排好的内容之后。

### 3.4 末尾几栏

数据给不出所在步骤的，放在全部步骤之后，各有标题：

| 标题 | 条件 |
| --- | --- |
| 任务完成后 | 说它的 NPC 所在的实体组以“本任务已完成”为条件 |
| 可以随时找 NPC 说的话 | 说它的 NPC 没有任何数据控制，也不在路线附近 |
| 可选：路过时才会听到 | 离所有路线都远，说它的 NPC 在本篇某段对话开始时离场 |
| **未定位的对话** | 没有任何 NPC、路人、脚本或区域引用它（只在自己的文本表里），或字符串池里都没有它。**阅读器默认收起**（开发者 2026-10-22） |

“未定位”只说明数据给不出位置，不说明游戏里没有：它可能由我们还没解码的机制播放，也可能是删减的内容，所以不写“可能已删减”。

### 3.5 嵌套任务

步骤的条件等另一个任务的步骤时，那个任务在这一步里播放，读在这一篇里，前面一行它的名字（`stage`）。对话 id 都写成外层任务的，按播放或说出它的关卡分：
只在内层任务的关卡里、不在外层的，归内层。**有自己剧情的任务不嵌套**：它是续作，不是这一篇的一部分（2026-10-22，全量推广时发现两个干员任务的第二篇被并进了第一篇）。

## 4. 写进库的样子

| `story_lines.kind` | 内容 | 检索 | 向量 |
| --- | --- | --- | --- |
| `step` | 步骤目标；末尾几栏的标题 | 不检索 | 不嵌入，切块在此断开 |
| `stage` | 嵌套任务的名字 | 不检索 | 不嵌入，切块在此断开 |
| `unplaced` | “未定位的对话” | 不检索 | 不嵌入，切块在此断开 |

- 步骤目标是**给读者的标题，不是证据**（开发者 2026-10-21）：`unsearchedLineKinds` + `searchableLinesFilter`，关键词 `search`、`grep`、按名字取材、资料页搜索、阅读器里的查找都排除它们。
  不过滤的话，“与某人交谈”这样的目标会被当成提到那个人的台词。**新加查 `story_lines` 的检索时要带上这个过滤。**
- 只有后面跟着对话的步骤才写标题：没有对话的步骤不写（全量时一半以上的步骤没有对话，写出来是一串空标题）；没有目标文字的步骤，它的对话读在前一个目标下；
  与上一个写出的目标相同的不重复写。报告里仍列出每一步。
- 阅读器（`story_reader_page.dart`）：`step` 是一条短竖线加文字，`stage` 更大；`unplaced` 可以点开，标题后是段数，引用或续读的行落在里面时自动展开。
  步骤标题之后，下一段重新写种类名。

## 5. 建库与审核

```bash
dart run tools/build_endfield_database.dart … --data=<unpack>/persistent/Data/Json --step-order=all --output=build/endfield --force
```

`unpack_endfield.ps1` 已带上这两个参数。`--step-order=<任务,…>` 只排这些任务，`--only-missions=<任务,…>` 只写这些任务的剧情（审核几个任务时用，库不能发布）。
不加 `--data` 时结果与 0.15 逐行相同。

每段对话去了哪一步、依据是什么，写在输出目录的 `story_order_report.md`：每步一节，每段一行 `` `id`（种类）[依据级别] 说明 ``。
审核一个任务就读它的报告和库里导出的全文；发现位置不对，记下 id 和应在的位置，再去数据里找能说明它的东西，找到才加规则。

## 6. 规则是怎么来的、怎么验证

- 规则是在伊冯的角色纪事（c17m1、c17m2、c17m3 与它嵌套的 c17m3d5）上逐段读原文找出来的：每发现一处与剧情不合，就找能说明它的数据，找到才加规则，
  找不到就承认找不到（放进末尾几栏）。先用 Python 原型试规则，每改一次通读一遍；Dart 版与原型逐项对照（235 项的顺序与依据完全一致）后才接进建库。
  开发者审核过这四段（2026-10-22）。
- **只在这一条线上逐段核对过**，阈值（30 米的宽区域、50 米的远近、5 米的目标处）也只来自它。其余任务的顺序没有人读过。
- 全量推广时（2026-10-18 客户端）的检查：294 个任务按步骤排；与不排的库比，每篇的行（去掉标题）完全相同，故事一篇不少；
  6392 段里 1431 段（255 篇）落在“未定位的对话”；1543 行步骤标题，每行后面都有对话。真实库验收（`endfield_acceptance_test.dart`）检查：
  标题后面紧跟一段、“未定位的对话”是一篇的最后一栏、没有占位文字、每个有定义的任务的集合都还有剧情。
- 换客户端时：重对类型名（§2.1）、重跑全量与验收、和上一个库逐篇比较（行的多重集合应只因新内容变化），再抽读几篇。

## 7. 还没做的

- “未定位的对话”约占按步骤排的对话的 22%（多是通讯和闲话）。有的可能由没解码的机制播放（任务定义里别的动作、Lua 脚本、别的子数据），
  要逐类看是哪里引用它们，再加规则。
- 只读过一条线。下一步应抽读不同种类的任务（主线、探索、委派、活动）各一两篇，按 §5 的办法修规则。
- 一步之内的种类先后是开发者定的约定，不是数据给的。
