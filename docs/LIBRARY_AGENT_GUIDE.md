# 资料页结构说明

资料页（图鉴）是知识库条目层（`collections` / `entries` / `entry_links`）的阅读视图。问答 Agent 在查库前先参考这份说明，
判断要找的东西在哪一类、对剧情有什么用。**正文以 `lib/core/agent/lore_agent_prompts.dart` 的 `loreLibraryGuide` 为准**
（它是系统提示词的一部分，主 agent 与子 agent 都会读到）；这里记录依据和维护办法。

## 结构概要

| 书架 collections.kind | 内容 | 对剧情的作用 |
|---|---|---|
| `main` 主线 | 每章一个集合，行动前/后剧情，章内关卡、敌人、物品、奖章 | 主干事件 |
| `sidestory` / `ministory` / `branchline` | SideStory、故事集、插曲 | 完整支线 / 短篇 / 与主线联系紧密的补充 |
| `activity` 其他活动 | 签到、玩法类 | 剧情少，活动文本/物品/奖章有设定 |
| `memory` 干员 | 档案、密录、悖论模拟、模组、皮肤、信物、召唤物 | 人物设定与个人经历 |
| `roguelike` 集成战略 | 结局、月度小队、区域/关卡、收藏品、事件、注释、开局剧情 | 叙事在结局与开局剧情，其余是设定氛围 |
| `sandbox` 生息演算 | 篇章、事件、关卡、物品、简介 | 剧情在篇章下的故事 |
| 图鉴（无集合/跨集合） | 敌人、物品、奖章、标志物、邮件、世界观、势力、人物 | 背景文字与旁证 |

依据（prts.wiki）：活动分类（SideStory/故事集/插曲，“插曲”是与主线联系紧密的支线）、干员密录与悖论模拟、档案随信赖解锁、
干员信物、集成战略的结局/月度小队/收藏品/密文板、生息演算为常驻玩法活动。界面上每个名字的出处写在 `lib/core/library/library_labels.dart` 的注释里。

## 终末地（0.12）

终末地是另一个库文件，表结构相同，所有 id 以 `ef/` 开头（书架 kind 也是，如 `ef/main`）。Agent 看到的说明在
`lib/core/agent/lore_endfield_prompts.dart`（装了终末地时并进系统提示），名词都取自游戏的界面文字（`TextTable` 的 `ui_*`/`LUA_*`），
层级对照 fz.wiki 与 warfarin.wiki。

| 书架 collections.kind | 内容 | 对剧情的作用 |
|---|---|---|
| `ef/main` 主线任务 | 每个任务一个集合，一篇剧情；`group_name` 是“第一章 · 进程Ⅰ · <进程名>”（游戏的 `ChapterInfo`），同组内按游戏顺序 | 主干事件 |
| `ef/discovery` / `ef/side` / `ef/activity` / `ef/other` | 探索、支线、活动、委派任务（游戏任务面板的分类），按任务所在地区分组 | 支线与日常 |
| `ef/world` 其他 | 地图上一处地点的交互文字和该地点的 Baker 话题、敌人遭遇的通讯 | 场景旁白 |
| `ef/unused` 未实装任务 | 客户端留着对话、游戏里没有的任务（旧版剧情、删掉的任务） | 不是游戏里发生过的剧情 |
| `ef/archive` 情报档案库 | 分页：中枢档案 / 见闻辑录（纸质记录、电子档案、藏品）/ 音像存档 / 情报采集（事件调查、调查报告）；文档按地区分组 | 设定与旁证 |
| `ef/memory` 干员 | 干员情报、干员档案、语音记录；角色纪事（干员任务，“篇章Ⅰ · <名>”）、Baker 话题（`ef/baker`）、帝江号互动（`ef/ship`） | 人物设定与个人经历 |
| `ef/codex` 百科 | 威胁（敌人，含分布地点）、武器、物品、关卡、来信 | 背景文字 |

一篇任务剧情里每段对话前有一行 `kind = 'section'` 写种类（对话、通讯、远程通话、闲话、短信）；种类之间谁先谁后游戏数据没有给出。

## 时间与同一人物

- 表里的 `start_time`（活动、故事目录）是**上线时间**，不是故事内时间。后上线的内容可以补充、修正、推翻先上线的叙述，其讲的事在故事里也可能更早。
  游戏数据里没有故事内的时间表（也没有干员的上线时间：`gacha_table` 只列了 82/458 个干员，不可靠），所以不提供“故事发生顺序表”，
  提示词要求 Agent 从原文（日期、几年前、人物状态、他人回忆）判断，不以上线顺序推断先后。
- 同一干员的不同版本来自 `char_meta_table.spCharGroups`（37 组，组内第一个是原型），建库时写 `same_person` 链接（异格 → 原型），
  干员页有“同一人物”小节。表里不区分“同一人物后来的经历”和“假设线”，所以也没有“是否假设线”的表；提示词要求读档案与剧情判断。
  阿米娅的职业形态（`char_patch_table`）不是独立条目，不处理。

## 维护

- 新增条目类型、书架、绑定关系时，同步改 `loreLibraryGuide`，并确认里面没有具体人物、章节、活动名（`test/core/agent/lore_agent_loop_test.dart` 守卫）。
- 提示词只讲结构与用法，不放示例；库里出现不认识的 kind/type/group_name 时，Agent 读原文判断，不猜含义。
- 界面名字的兜底顺序（`library_labels.dart`）：表或 prts 给的名字 → 所属家族的默认名（集成战略资料、生息演算资料、档案资料、活动资料）→ 类型 id；
  未知书架显示“其他”，未知绑定显示“相关”，没有名字的分组不显示标题。
