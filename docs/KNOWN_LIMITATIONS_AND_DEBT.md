# 已知限制与技术债

> 基准：v0.12.0 正式版（2026-10-09）。只列**仍开放**的问题；已关闭的历史（R8–R16 的分步流程、旧 ReAct、debug 签名、Wiki 爬虫等）见 git 历史与 CHANGELOG。
> 新增条目写清：现象、根因、当前缓解、修复方向或触发条件。

## 1. 知识库与检索

| 问题 | 根因 / 现状 | 缓解与方向 |
| --- | --- | --- |
| 中文全文索引基本无效 | FTS5 `unicode61` 不分中文词 | 原文检索用 LIKE（按命中行数排序）+ 可选向量；中文分词 FTS（trigram）未做，LIKE 在 44 万行上全表扫描（桌面 <1 s） |
| 没有组织/概念级汇总实体 | 组织、地点、概念没有可枚举的表，只能从文本涌现 | Agent 用 `grep` 全库统计 + 读原文；不建人工词典（会把方向写死） |
| 人物身份只能在问答时确认（设计如此） | 代号/真名/“？？？”/冒名/夺舍都是剧情解读 | 只保证检索可达（读音近似名）；揭示身份的那一行没读到时，答案停在“资料未覆盖” |
| 干员“特性”文字（玩法）仍在库里 | 召唤物/装置条目只有这一段，去掉条目会消失 | 待开发者决定；可改为只给 token/trap 保留 |
| 推断出的结构 | 肉鸽事件的选项层级、生息演算事件的场景顺序，表里没有直接给出，按排列推断 | 规则写在 `event_outline.dart` 与文档；出现明显错层时再按新表结构修 |
| 没有向量 key 时只有字面检索 | 向量需要用户配置服务 | `find` 写明退回原因；写错的名字靠近似名 |
| 知识库下载在部分网络上卡住 | 手机到 GitHub 资产域名的连接不应答（未能复现根因） | 阶段显示、45 s 超时、6 次新连接、取消、手动放置 `.download.gz` 的退路 |

## 2. 问答 Agent

| 问题 | 现状 | 方向 |
| --- | --- | --- |
| 耗时 | GLM 一题 4–6 分钟（带工具的调用有 4.5–6 s 底噪；答案文本写 3 遍） | 复核/提要可在输入框工具栏关闭；降本改动需单独立项 |
| 审稿依赖模型对作品的记忆，提什么有波动 | R18 审稿子 agent 只提故事层面的问题，结论仍由主 agent 读原文决定 | 不加针对某类剧情的检查项（CLAUDE.md） |
| 提示词没有规定回答语言 | 英文界面的用户也得到中文回答 | 按界面语言加一句通用要求 |
| 在问答进行中保存设置可能中断当前问答 | 设置变化会重建 client provider | 保存时若有进行中的问答，延后生效 |
| 评测集标准答案未人工审核 | `test/fixtures/investigation_eval.json` 是草稿 | 只作参考，不作通过门槛 |

## 3. 界面

| 问题 | 现状 |
| --- | --- |
| Wiki 悬浮栏 | 网页铺满，靠注入 `html` 上下留白与平移站点自己的 fixed/sticky 栏；个别站点的结构可能仍被遮住，真机逐站确认 |
| 阅读页没有滚动条，不能一键拖到末尾 | 惰性列表从锚点双向建，总高度靠滚动逐步校准；这是“任意长的故事打开不卡”的代价 |
| 条目类型/分组/绑定名只有中文 | `library_labels.dart` 是游戏内容用语，与库内容同语言；LLM 错误信息中英混杂 |
| iOS 未验证 | `IOS_SETUP_GUIDE.md` 停在 v0.9；0.10/0.11 只在 Android 上测过 |

## 4. 工程

| 问题 | 现状 |
| --- | --- |
| 真机性能未量化 | 只有桌面计时（资料页查询最慢 96 ms、向量检索 27 ms）；手机上的冷启动、内存峰值、安装耗时没有记录 |
| 没有自动截图对比 | Widget 测试有溢出断言；资料页布局截图可导出（`ARKLORES_SHOT_DIR`），没有 golden 基线 |
| 测试覆盖偏低的部分 | 设置页、知识库页的界面分支、`rag/chunker.dart`；WebView、Android 前台服务、启动图标切换只能真机检查（`test/README.md`） |
| 长文件 | `wiki_browser_page.dart`、`lore_agent_loop.dart`、`arknights_importer.dart`、`chat_bubble.dart`、`story_reader_page.dart` 各是一个整体，未拆 |
| 签名 keystore 只有维护者一份备份 | 丢失后无法再发布可覆盖安装的版本 |

## 5. 终末地知识库（0.12）

| 问题 | 现状 |
| --- | --- |
| 只能在电脑上从游戏客户端重建 | 没有可增量跟随的社区仓库；App 里没有终末地的“检查更新/构建”，只能下载发布的资产（`tools/unpack_endfield.ps1`） |
| 一个任务里不同种类的对话谁先谁后不知道 | 对话、通讯、远程通话、闲话各自编号；关卡脚本只把约三成任务对话连到任务步骤，过场对话由时间线触发（kit 也认为激活顺序未解决）。现在按种类分块、块内按编号，提示词告诉 Agent 不要跨种类推断先后 |
| 少数台词仍按行号 | 约 11% 的台词行既不在对话树里也不在时间线片段里（多为地图交互对话），按行号排、选项按组号填空位；一段对话有几条时间线时（14 段）各条的台词混排在第一个过场处；时间线里按选项分支的片段没有展开 |
| 主角台词只收女性版本 | `{F}…{M}…` 两种写法只留一种（kit 默认）；男性版本不在库里 |
| 未实装任务里有无名的 | 没有任务定义的任务（客户端留着对话、游戏里没有）放在“未实装任务”书架；其中 6 个游戏哪里都没有名字，叫“无名任务（<任务 id>）” |
| 档案、语音的解锁条件不收 | “信赖度达到亲近可解锁”这类条件是玩法信息，不进库（fz.wiki 页上有） |
| 干员简介不在客户端里 | fz.wiki 干员页开头的“干员简介”在客户端的表里找不到（应是官网文案），库里没有 |
| 向量随资产发布，App 里不能补 | 终末地资产（v0.12.0）带剧情向量；“故事向量”卡片只管明日方舟库。重建终末地库后要用 `unpack_endfield.ps1 -Embed` 重新补 |
| 势力表为空 | 当前客户端的 `BlocDataTable` 是空的；势力名改从干员的阵营标签取（`CharacterTagTable` → `TagDataTable`） |
| 闲话多半没有说话人 | `EnvTalkTable` 的 `actorId` 大多为空，这些行在库里不带说话人 |
| 部分来信看不出寄信人 | 委托回信的寄信人 id 在 NPC 表里查不到名字，只留游戏给的标题 |

## 6. 范围

- 明日方舟与终末地是两个独立的库；跨游戏只在检索面合并（`MultiGameRetrieval`），不建跨游戏的关系。
