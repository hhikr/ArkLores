# 角色扮演去留分析（0.11 立项，2026-10-04）

> 结论：**不重构角色扮演，也不把它排进 0.12。** 现有角色扮演页冻结（只修会崩的问题，不加功能）。
> 0.11 把力气放在“资料页：阅读器 + 用户资料”（见 `V0.11_PLAN.md`）。
> 开发者的判断标准是“如果和成熟 app 完全重合就没有开发意义（不是为了盈利和竞争，是爱好）”，下面是依据。

## 1. ZOOT! 是什么（公开资料，未实机使用）

来源：B 站《ZOOT!终端 正式版宣传 PV》、第三方下载站介绍页（见文末）。以下是它自己宣传的内容：

- 作者 Kiiinou，**非官方**，免费；Android 版和 Windows 版。
- “全干员、全数据、完整生态终端”：与**所有干员一对一聊天**，还原性格、语气、情绪基调。
- **群聊**（把多名干员拉进同一个群）、**动态 / 朋友圈 / 评论**（干员发动态、评论也由模型生成）。
- 可编辑干员**人设与活跃度参数**；需要用户自备 API Key 与模型，内容全由第三方模型生成。
- 宣传里还提到“罗德岛终端”“全知识图谱支持”“叙事模拟与个人效率工具”。

没有公开的信息：是否开源、是否离线、记忆机制的细节、知识数据怎么更新、是否给出原文出处。
**限制**：以上来自宣传页和下载站，我没有装机测试；开发者如果想确认，装一下试 10 分钟即可（下面“如果要翻案”一节说明看什么）。

## 2. 和 ArkLores 的重合度

| 维度 | ZOOT! | ArkLores 现状 |
| --- | --- | --- |
| 与干员一对一聊天、人设、语气 | 核心功能，宣称全干员 | 有，但质量差（开发者自己的评价） |
| 群聊、动态、朋友圈等“罗德岛环境模拟” | 有 | 没有 |
| 人设/活跃度可编辑 | 有 | 没有 |
| 数据覆盖 | 宣称“全数据/全知识图谱” | 全量 GameData（约 4750 个说话人、1370 个干员、2816 个剧情文本共 41 万行，另有档案、语音、肉鸽、敌人、道具等），可跟上游解包更新 |
| 平台 | Android + Windows | Android（Flutter，可扩展） |
| **带行级原文出处的问答** | 未见 | **有（项目的核心）** |
| 剧情阅读与定位 | 未见 | 有（原文阅读页，0.11 要扩成资料页） |

角色扮演这个形态上，ZOOT! 已经把“和干员聊天 + 群聊 + 朋友圈 + 人设编辑”做成了成品，而且是专门做的，复杂度比
ArkLores 能投入的高。ArkLores 在这条线上没有结构性优势：

- “数据是实时更新的、可查原文”确实是 ArkLores 的特点，但它的**价值体现在问答和阅读上**（回答要有出处）。对角色扮演来说，
  用户要的是语气和情景沉浸，而不是出处；ZOOT! 也宣称有全数据。
- 唯一还没被覆盖的缝隙是“**严格按剧情时间线 / 不剧透的扮演**”和“**扮演里随时可点开原文核对**”。这是一个功能，
  不是一个产品，需要先有可靠的阅读 / 定位 / 时间线数据（恰好是 0.11 资料页要做的东西）。
  所以它是资料页的**后续应用**，不是现在重构角色扮演的理由。

## 3. 决定

1. 不做“仿酒馆（SillyTavern）”式的完全重构：功能面（卡片、世界书、群聊、朋友圈、扩展）远超一个业余项目的投入，
   且与 ZOOT! 的路线重合。
2. 现有角色扮演页（`roleplay_agent.dart`、`roleplay_tab.dart`、`roleplay_session_store.dart`）**冻结**：保持可用，
   不加功能；`search_local_lore` 仍是它唯一的事实来源（原则不变）。
3. 是否从界面中移除它，等 0.11 资料页稳定后由开发者决定（移除成本很小：一个 tab、一个 agent、一个 session store）。
4. 如果以后要碰角色扮演，先做“剧情时间线感知”这类建立在资料页之上的小功能，而不是重做聊天 app。

## 4. 如果要翻案（装 ZOOT! 试用时看什么）

- 它的干员知识是否准确到“能区分剧情进度（不剧透）”？还是只有人设？
- 能不能看到干员说某句话的依据（原文）？
- 数据是随解包更新还是随 app 版本更新？更新多快？
- 有没有记忆（长期对话里记得前面发生的事）？

只要这几项里有两项以上它明显没做到，而且开发者觉得想做，就可以把“带出处、不剧透的扮演”作为 0.12 的候选重新立项。
