# 角色扮演去留分析（0.11 立项，2026-10-04）

> **结论：不重构角色扮演，0.11 做资料页，0.12 也不排角色扮演重构。** 现有角色扮演页冻结（只修崩溃，不加功能）。
> 开发者的标准：“如果和成熟 app 完全重合就没有开发意义（目的不是盈利竞争，是爱好）”。
> 按这个标准，“仿酒馆的聊天式角色扮演”与 ZOOT! 重合；ArkLores 剩下的独特之处在**有出处的原文**，
> 它对阅读和问答有价值，对沉浸式聊天几乎没有。下面是依据。

## 1. ZOOT! 是什么（公开资料；未装机试用）

来源见文末。以下是作者的说明和评论区里能确认的部分：

- 作者 Kiiinou，**非官方**同人软件，免费；Android 与 Windows 两端，“除去工作于本地局域网的不同结点功能外，基础功能基本一致”；
  没有 iOS 版。通过网盘分发（未见源码仓库），有 QQ 交流群。v1.0 正式版 2026-08-11 发布。
- 自我定位：“基于明日方舟世界观下的虚构角色交互，**叙事模拟**与个人效率工具”；宣传语“全干员 全数据 完整生态终端”。
- 功能（简介 + 下载站 + 评论区）：
  - **全干员一对一聊天**，按原作设定还原性格、语气、情绪。
  - **群聊**，以及干员发**动态、评论**（也由模型生成）。
  - 可调**人设参数与活跃度**。
  - **世界经济模拟**：评论区有人在 app 里“投资谢拉格和乌萨斯大跌”、亏掉龙门币；作者在评论区说会发兑换码。
    也就是说，它已经有一层“罗德岛/泰拉环境”的模拟玩法，不只是聊天。
  - 局域网“结点”功能（具体内容未公开）。
  - 自备 API Key 与模型；接入了未成年人保护。
- 热度：宣传 PV 约 33.5 万播放、2.4 万赞、1.8 万收藏、1300+ 评论（2026-10-04 查询）。有用户群和持续更新的作者。
- 没查到的：知识数据怎么来、多久更新、有没有记忆和剧情进度控制、能不能给出原文出处、是否离线。
  **限制**：没有装机测试，PV 的实机演示也只看了文字信息。

## 2. 重合度

| 维度 | ZOOT! | ArkLores |
| --- | --- | --- |
| 与干员一对一聊天、人设、语气 | 核心功能，全干员，可调参数 | 有，但开发者自评“太烂” |
| 群聊、动态/评论、世界经济等环境模拟 | 有 | 没有 |
| 平台 / 用户 | Android + Windows，有社区 | Android，个人使用 |
| 数据 | 宣称“全数据/全知识图谱”，来源未公开 | 全量中文 GameData：2816 个剧情文本（41 万行）、9.7 万条结构化记录、839 份干员档案；可按上游解包增量更新 |
| **带行级原文出处的回答** | 未见 | **有（项目核心）** |
| **离线读原文、定位到行** | 未见 | 有（证据链 → 原文阅读页；0.11 扩成资料页） |

**判断**：

1. **聊天式角色扮演完全被覆盖。** “仿酒馆的完全重构”要做的角色卡、世界书、群聊、记忆、扩展，ZOOT! 已经作为专门产品做出来了，
   还多了环境模拟，有社区，作者在持续更新。业余时间重做一遍，结果只会是一个更弱的 ZOOT!。
2. **ArkLores 的数据优势用不到角色扮演上。** “数据可跟上游更新、每句话可查原文”的价值在于让回答**可核对**。
   沉浸式聊天要的是语气和情景，用户不会去点出处；而“全数据”这个卖点 ZOOT! 也有。
3. **唯一没被覆盖的缝隙**是“**严格按剧情进度、不剧透、随时可点开原文**的扮演”。这是一个功能而不是一个产品，
   而且它需要的基础（可靠的章节目录、阅读进度、按时间线定位）恰好是资料页要做的。它是资料页之后的**候选应用**，
   不是现在重构角色扮演的理由。

## 3. 决定

1. 不做“仿酒馆（SillyTavern）”式完全重构；0.12 也不预排。
2. 现有角色扮演（`roleplay_agent.dart`、`roleplay_tab.dart`、`roleplay_session_store.dart`）**冻结**：保持可用，只修崩溃，
   不加功能；`search_local_lore` 仍是它唯一的事实来源。
3. 0.11 做资料页（`V0.11_PLAN.md`）。资料页稳定之后，由开发者决定是否把角色扮演从界面移除（成本很小：一个 tab、一个 agent、
   一个 session store）。
4. 以后如果要碰扮演，只考虑建立在资料页之上的小功能（按阅读进度限制知识范围、扮演中点开原文），并且要单独立项。

## 4. 如果要翻案（装 ZOOT! 试 10 分钟看什么）

- 它的干员知道的内容能否**按剧情进度**限制（不剧透），还是只有人设？
- 能不能看到干员某句话的**依据**（原文）？
- 数据随解包更新还是随 app 版本更新？新活动上线后多久能聊？
- 长对话里**记得**前面的事吗？

如果有两项以上它明显做不到，而开发者又想做，可以把“带出处、不剧透的扮演”作为资料页之后的候选重新立项。

## 5. 顺带：资料页（阅读器）的同类

资料页也不是没有同类，这里一并说清楚，免得重复同样的问题：

- [PRTS Wiki](https://prts.wiki/)：在线，剧情和档案最全，社区维护。
- [明日方舟剧情阅览](https://arknightsplot.vercel.app/)：在线网页，含主线、支线、故事集、集成战略剧情、干员密录、漫画/世界观、
  敌人/道具/家具档案和时间线。
- [RhodeIsland-Remote-Terminal](https://github.com/ChaomengOrion/RhodeIsland-Remote-Terminal)：Unity 本地工具箱（剧情播放、角色查询），
  作者说明已不保证兼容当前版本。

阅读器本身不是空白生态位。0.11 仍然值得做，原因是**开发者自己的需求**：

- 手机上离线读；
- 和问答的证据链是同一个阅读器（答案 → 原文 → 继续往下读 → 回到问答）；
- 阅读历史与定位；
- 数据跟解包更新；
- 自己的资料和官方原文放在一起管理、搜索。

这些放在一起，现有的网页工具都不提供。所以 0.11 的设计重点是**和问答打通**，而不是做一个更全的 wiki。
